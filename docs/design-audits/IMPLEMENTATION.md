## Payload gaps / named follow-ups

- **Add-a-backend split preview + GPU/System RAM tiles** (add-backend-card Q8 remainder): the creation split is computed in Rust by `backend_add` (src-tauri/src/main.rs) using the wizard's tensor-split algorithm over live telemetry VRAM totals plus existing backends' memory requirements. `placementPropose(modelId, split, backendId?)` (api.ts) only projects a GIVEN split and cannot assign one for a not-yet-created backend; `ModelRow` carries no per-model gpu_ram_mib/sys_ram_mib (those are per-backend figures on `BackendRow`). Closing this needs a propose-assignment payload for a hypothetical backend. The card ships the Context and Size tiles the payload does carry.
- **Gateway summary Groups count semantics** (gateway-summary-card F4-adjacent): `gateway_status.groups` counts CONFIGURED groups, including disabled ones that generate no config, while the Groups tab shows enabled state per card. Whether the summary value should count enabled-only is a payload-semantics decision for Pete; the UI renders the payload value as-is.
- **GPU view overview-strip duplication** (gpu-card Q6 note): the GPUs overview strip repeats Util/VRAM/Temp/Power that the cards also carry. The audit's recommendation — overview keeps the numbers as the cross-GPU comparison surface, cards keep the residency bar + tiles — is what shipped; flagged for Pete rather than restructured unilaterally.
- **OpenRouter cap-vs-spend** (openrouter-tier-card): `GatewayOpenRouter` carries no spend/usage field, so no cap-vs-spend bar is possible; the audit itself proposes none. Recorded so the absence is a decision, not an oversight.

## Batch re-score — 14-question checklist (2026-10-16, after implementation)

Scored across the surfaces this batch touched, against docs/design-principles.md Part 3:

1. **Compact** — Pass. Settings is one tabbed card; wizard detail, GPU processes, routing-rule fragments, add-model optional fields, MXC rule lists, and model details all sit behind toggles/expandables.
2. **One section, multiple views** — Pass. Routing = one section with Flow/Groups tabs; MXC rules = one block with a segmented filter; Settings = one section, four tabs.
3. **Prime real estate** — Pass. GPU and backend cards lead with residency bars; the plan card leads with count tiles + scope bar; the gateway traffic block leads with the distribution bar.
4. **Narrative in tooltips** — Pass. Every audited inline sentence moved verbatim into an info-tip, a chip tooltip, or a collapsed expandable (the destinations principle 5 allows).
5. **Real data** — Pass. Every bar/fill encodes a payload value; where widths are equal by construction (group membership, configured membership fallback in Flow), the bar's tooltip states that basis instead of implying traffic.
6. **Numbers in one place** — Pass, with two recorded exceptions: plan counts live only in the plan card's tiles (the pending-changes header deliberately omits its count — see the reconciliation note on the Pending changes row), and the GPU overview-strip duplication is retained per the audit's own recommendation (follow-up below).
7. **Density with order** — Pass. Summary-first everywhere: MXC order inverted to Mode → policy → activity → self-test; GPU models above processes; gateway lifecycle actions directly under the summary card.
8. **Multi-number data is a chart** — Pass, one named remainder: gateway traffic distribution, error shares (gateway + model), MXC decision mix, plan scope mix, routing-rule sources, and download progress are all charted; the add-a-backend split preview awaits a propose-assignment payload (gap below).
9. **Label: Value** — Pass. Visible strings on touched surfaces are noun labels with values, chart keys, or control labels; sentences survive only inside tooltips/expandables.
10. **Copy buttons** — Pass. Base/LAN URLs and master key (earlier), OpenRouter credential reference, generated YAML (Copy + Download), Settings paths, model SHA-256 (header + Details) and file path, plan manual command.
11. **Status colors** — Pass. Amber is transitional only (wizard running, model downloading/paused/verifying, plan restart class, MXC prompt); gray = disabled/stale/excluded/not-checked; green = enabled/running/adopted/allow/present; light red = failed/stopped/deny/partial/download-failed.
12. **Unknown is not zero** — Pass. The sys_ram_mib "0 GiB" bug is fixed; model stats `?? 0` coercions removed; credential probe null renders a "not checked" chip; any unmeasured GPU process collapses the residency bar to a single neutral segment; VRAM total 0 renders "not measured"; pending-changes fetch failure renders an unavailable/error state, never "every change is live".
13. **Empty states** — Pass. Unconfigured OpenRouter tier, zero routing rules, zero placements, empty settings blocks, and placeholder prose lines all render nothing; the wizard/settings/logs placeholder sentences are deleted.
14. **Number formatting** — Pass. fmtCount (thousands separators), fmtPct, and trim1 route every number on touched surfaces, including the summarizeValue path that previously leaked raw config numbers.

Gates: `npm run build` (tsc --noEmit + vite) passes; `npm run smoke` passes (all bundle checks; no smoke expectation changes were needed — the smoke suite asserts bundle/command integrity, not card structure).
