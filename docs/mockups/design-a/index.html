Design A — Dense Developer Console · Graphic Mockups

Visual mockups for the eight windows in design-a.md, rendered at 1600×1000. Dark developer aesthetic, 13px dense type, tabular numerals, status vocabulary ok / degraded / failed / starting / stopped. Data reflects the actual stack: Dell Precision 7865, RTX A4000 16GB + 2× Tesla P100 16GB, Qwen3.8-27B / Qwen3-Coder-30B / Qwen2.5-Coder-7B / Qwen3-8B, LiteLLM gateway, Windows ML backend, MXC policies.

01Stack Provision
First-run setup wizard: ordered dependency chain (prerequisites → binaries → models → integrations → health check), per-step status with detected-vs-required versions, live run log, GPU fit strip, exportable run report.
02Service Console
Main dashboard: flat services table (status, endpoint, model, GPU, VRAM, uptime, tok/s sparklines, inline actions), GPU strip with per-process VRAM attribution, task drawer, slide-in context panel with Summary / Config / Logs / Test tabs.
03GPU Detail
Per-GPU hardware view: 60s metric charts, readout block (driver, CUDA, clocks, PCIe, fan N/A stated explicitly), process attribution with unmanaged-process kill, tensor-split placement map, compare overlay.
04Model Library
GGUF management: storage summary, per-model rows (quant, size, role, placement, fit-check, loaded status), expandable detail (source, checksum, layer map, used-by), download queue with pause/resume and fit-check gate.
05Logs
First-class log surface: process filter rail with line counts, level filters, merged stream with per-process tags, errors-only toggle, ring-buffer paging, export and clear-buffer controls.
06Settings
Defaults tab: global-default → per-backend override chain with validated fields, changed-from-default and restart-required markers, inline validation errors that block save, read-only override summary.
07MXC Policies
Sandbox policy editor: policy-set list, structured rule rows (tool pattern, scope, decision, conditions), simulate-before-deploy with verdicts, recent-decisions audit trail, dry-run toggle, versioned deploys.
08History
Auditable past: drift alerts for components off pinned versions, timeline of provisioning runs, updates, repairs and config changes with actor, duration, per-run logs and rollback.
